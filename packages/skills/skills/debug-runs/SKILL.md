# Debug runs

Find the cause first, then suggest the smallest fix. Only read: don't start, continue, stop or delete a run unless asked.

## Look

Run `kombinat` from the folder with `routines/`, with its package manager: `npx kombinat`, `pnpm kombinat` or `yarn kombinat`.

1. `kombinat validate`. A file with a wrong value stops the schedule of every routine. In another folder, it finds no files and says ok.
2. `kombinat list`. Each routine with its next run and how its last run ended.
3. `kombinat status`. Whether the installed daemon runs, when it last checked the routines, and the times each routine skipped, with the reason: `disabled`, `already_running` or `nothing_to_do`.
4. The run's record, `~/.kombinat/runs/<routine>/<id>.json`. The newest id sorts last. Read `status`, `error`, `resultText`, `trigger` and `blockedActions`.
5. What the agent did: `curl -s http://localhost:7433/api/runs/<routine>/<id>/transcript`. It holds the check and the hooks too.
6. The daemon's log, `~/.kombinat/daemon.log` and `daemon.err`. A `tick failed` line means that no routine starts. With `kombinat serve` in a terminal, the log is in that terminal.

`~/.kombinat` and port 7433 are the defaults. `KOMBINAT_STATE_DIR` and `KOMBINAT_PORT` change them.

## Causes

| What you see                                   | Cause                                                                                                                                                                                                                                                                                               | Fix                                                                                                                                                                                                                                                     |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No routine starts                              | The daemon is down, or a routine file has a wrong value                                                                                                                                                                                                                                             | Have the user start it with `kombinat serve` or `kombinat install`, or fix what `kombinat validate` reports                                                                                                                                             |
| A merged change is not live                    | The daemon reads the `routines/` of its own folder. It pulls `main` only while that folder is on `main` and has no local changes                                                                                                                                                                    | The log has a `git pull skipped` line with the reason. Commit or drop the changes in that folder                                                                                                                                                        |
| One routine did not start at its time          | It is `enabled: false`, it still ran, its `check` found nothing to do, or 3 other runs were at work. A time lost to that limit of 3 is dropped and leaves no skip, only a `concurrency limit` line in the log                                                                                       | Nothing, when the skip is right. Otherwise shorten the run, fix the `check` or move the routine to another minute                                                                                                                                       |
| `failed` before the agent started              | The `cwd` or the agent's binary is missing, `check` or `before` failed or took over 3 minutes, `worktree: true` has no git repository, or its `account` is not signed in                                                                                                                            | The run's `error` says which. For an account, `kombinat login <name>`                                                                                                                                                                                   |
| `succeeded`, but the work is not done          | Claude was denied what needs approval. The Inbox files such a run under Needs a look                                                                                                                                                                                                                | `blockedActions` has the rule for each. Add them to `permissions.allow` of `.claude/settings.json` in the `cwd`                                                                                                                                         |
| `succeeded`, but the agent says it could not   | The agent gave up, and its exit was still normal                                                                                                                                                                                                                                                    | Fix what stopped it, and add `onAgentGiveUp: fail`                                                                                                                                                                                                      |
| `timed_out`                                    | The work took longer than `timeoutMinutes`                                                                                                                                                                                                                                                          | Raise it, or give a run less work                                                                                                                                                                                                                       |
| `failed` with "Reached the budget of … tokens" | `maxBudgetTokens` stopped it. A run that `maxBudgetUsd` stopped fails with Claude's own error                                                                                                                                                                                                       | Raise it, or give a run less work                                                                                                                                                                                                                       |
| `waiting`                                      | The Claude plan is at its usage limit                                                                                                                                                                                                                                                               | Nothing: it continues after the reset                                                                                                                                                                                                                   |
| `retrying`                                     | An attempt failed, and the next one starts 5 minutes later                                                                                                                                                                                                                                          | Nothing yet. `retry.error` says why it stopped                                                                                                                                                                                                          |
| `aborted`                                      | The process of the run is gone, such as after the computer restarted. Its `after` did not run                                                                                                                                                                                                       | Run it again                                                                                                                                                                                                                                            |
| A webhook starts no run                        | The answer says why: 200 with `"runId":null` the gate skipped it, 200 with a run id it waits while the routine runs, 401 the gate rejected it, 404 no `webhook: true` or a wrong name, 409 disabled, 413 a body over 256 KB, 429 a full queue, 500 a broken routine file, 504 a gate over 3 seconds | `curl -s http://localhost:7433/api/routines/<name>` lists the last calls in `webhookCalls`, with the reason of a rejection. No call there: the request did not reach the daemon, so check the tunnel. For the gate, see the `write-webhook-gates` skill |
| A routine with `startsAfter` does not start    | It is `enabled: false`, the run before did not end as `startsWhen` asks, it ended before `startsAfter` was added, or the routines make a loop                                                                                                                                                       | Fix `startsWhen`, or what `kombinat validate` reports                                                                                                                                                                                                   |
| Findings are filed under Nothing to report     | The answer starts with "No" or "Nothing"                                                                                                                                                                                                                                                            | Have the prompt start such an answer with another word                                                                                                                                                                                                  |
| It runs every time and mostly finds nothing    | It has no `check`                                                                                                                                                                                                                                                                                   | For a scheduled routine, add one that exits 78 when there is nothing to do                                                                                                                                                                              |

With `worktree: true`, the agent works in a worktree, which holds only what git tracks, so commit `.claude/settings.json`.

## Answer

Give the cause in one line, what shows it, such as the error or the step of the transcript, and the fix. Change a routine with the `write-routines` skill, then run `kombinat validate`. Offer a test run with `kombinat run <name>`. It does the real work, so ask first.
